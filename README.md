# Тоннель FW

**Тоннель FW** — Windows-утилита, которая разрешает приложениям выходить в интернет только при включённом VPN.

Она решает задачу, которую не закрывает обычный «запускатор по ярлыку»: даже если VPN отключился после старта программы или `.exe` запущен напрямую, приложение **не получает доступа к сети**. Ограничение работает на уровне брандмауэра Windows, а не только в момент запуска.

## Возможности

- Создаёт ярлыки на рабочем столе с компактным значком и отдельным `AppUserModelID` (ярлык можно закреплять на панели задач).
- Проверяет состояние VPN-адаптера перед запуском цели и не запускает её, если VPN выключен.
- Устанавливает **per-app kill switch** через брандмауэр Windows: сетевой доступ только через выбранный VPN-адаптер.
- Показывает текущее состояние адаптера в реальном времени (обновление раз в секунду и по событиям сети).
- Поддерживает светлую и тёмную темы Windows, список приложений `shell:AppsFolder`, поиск, выбор `.exe` и ссылку `https://`.
- Позволяет удалить созданные правила брандмауэра одним нажатием.

## Как это работает

Есть два уровня защиты.

**1. Проверка при запуске.** Ярлык передаёт приложению имя VPN-адаптера и цель запуска. Если адаптер не находится в состоянии `Up`, программа не стартует и показывается предупреждение.

**2. Ограничение в брандмауэре.** При создании ярлыка для `.exe` (если включена опция «Только через VPN») создаются два правила исходящего трафика:

| Правило | Действие | Область |
|---|---|---|
| `TunnelFW-B-<хеш>` | **Block** | все сетевые адаптеры, **кроме** выбранного VPN |
| `TunnelFW-A-<хеш>` | **Allow** | только выбранный VPN-адаптер |

В Windows блокирующие правила имеют приоритет над разрешающими. Поэтому:

- при включённом VPN трафик идёт через VPN-адаптер — срабатывает только разрешение;
- при выключенном VPN путь через физический адаптер закрыт блокирующим правилом;
- приложение остаётся без сети, **даже если запустить `.exe` напрямую**, минуя ярлык.

Имена правил детерминированы из пути программы (MD5-хеш), поэтому повторное создание ярлыка обновляет правила, а не добавляет дубликаты.

Правила записываются с повышением прав (UAC). Если приложение уже запущено от имени администратора, запрос не появляется.

## Использование

1. Запустите `TunnelFW.exe`.
2. Выберите программу кнопкой **«Выбрать .exe…»** (например, Claude Desktop), либо найдите её в списке, либо вставьте ссылку `https://…`.
3. Введите название ярлыка.
4. Выберите VPN-адаптер в выпадающем списке.
5. Оставьте флажок **«Только через VPN (брандмауэр Windows)»** включённым и нажмите **«Создать ярлык на рабочем столе»**.
6. Подтвердите запрос UAC. Готово: программа выходит в сеть только через выбранный VPN.

Чтобы убрать ограничение, выберите тот же `.exe` и нажмите **«Удалить правила»**.

### Режим ярлыка

При запуске с двумя аргументами приложение работает как шлюз:

```cmd
TunnelFW.exe "<VPN-адаптер>" "<путь или ссылка>"
```

Если адаптер не подключён, цель не запускается и показывается предупреждение. Именно так работают созданные ярлыки.

## Ограничения

- Ограничение через брандмауэр работает **только для `.exe` с полным путём**. Для ссылок (`https://…`) и приложений Windows из `shell:AppsFolder` снимите флажок — остаётся только проверка VPN при запуске через ярлык.
- Правила привязаны к конкретному пути `.exe` и имени VPN-адаптера. После переустановки программы или смены адаптера создайте ярлык заново.
- Правило `-Program` действует на один процесс. Если приложение выводит сетевую активность через **другие** исполняемые файлы (хелперы, `node.exe` и т.п.), для них нужны отдельные правила.
- Список «чужих» адаптеров фиксируется в момент создания правил. Если позже появится новый сетевой адаптер, повторите создание ярлыка.
- Удаление ярлыка с рабочего стола **не удаляет** правила брандмауэра — используйте кнопку **«Удалить правила»**.

## Проверка и удаление правил вручную

```powershell
Get-NetFirewallRule -DisplayName 'TunnelFW-*' |
    Format-Table DisplayName,Enabled,Direction,Action

Get-NetFirewallRule -DisplayName 'TunnelFW-B-*' |
    Get-NetFirewallInterfaceFilter
```

```cmd
netsh advfirewall firewall delete rule name="TunnelFW-B-<хеш>"
netsh advfirewall firewall delete rule name="TunnelFW-A-<хеш>"
```

## Сборка из исходников

Нужны Windows и встроенный компилятор .NET Framework (`csc.exe` из `Microsoft.NET\Framework64\v4.0.30319`).

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "src\build.ps1"
```

Сборка создаёт `TunnelFW.ico` и компилирует `TunnelFW.exe` в корне проекта.

- Исходник: `src/TunnelFW.cs`
- Скрипт сборки: `src/build.ps1`
- Версия сборки: 2.1.0.0
